# 电子病历评级约束（对接时不得破坏）

本文件约束 Medcius 在医院环境中的**能力边界**。分级标准以国家卫生健康委《电子病历系统应用水平分级评价标准》及医院当期测评细则为准；下列级别描述用于判断「插件可以做什么 / 不能做什么」，不是评级辅导。

## 1. 分级（0–8）与本插件关系

| 级别 | 含义（摘要） | 对 Medcius |
|---|---|---|
| 0–2 | 未形成全院电子病历或仅部门内系统 | 只处理用户粘贴/导出的文本；禁止直连生产库 |
| 3 | 部门间数据交换 | 只读中间库须信息科授权；本插件默认不连库 |
| 4 | 全院信息共享，初级决策支持 | 抽取与编码**不得**冒充医院 CDS；三级医院常见门槛 |
| 5 | 统一数据管理，中级决策支持 | 不得把模型输出写入医嘱、诊断、过敏史主数据 |
| 6 | 全流程闭环管理 | 不得绕过医嘱闭环、处方审核、手术申请既有环节 |
| 7–8 | 质量安全持续改进 | 插件输出须可审计（span、出处、版本）；不能无痕改病历 |

互联互通成熟度测评（四级甲/乙、五级甲/乙）要求共享文档与术语一致。Medcius 输出的诊断/手术**原文**可作共享文档素材；**编码**必须来自本地校验过的医保版码，不能凭记忆填写。

## 2. 不可破坏的评级相关能力

对接或试用时，下列行为视为违反本技能：

1. **回写生产 EMR。** 抽取结果、编码建议、审方结论默认只读展示。没有信息科书面授权，不得调用写入接口。
2. **替代医师诊断。** 电子病历评级中的临床决策支持是医院自有知识库/规则。Medcius **不做诊断决策**，不生成鉴别诊断，不根据化验升阶诊断。
3. **替代药师审方闭环。** 处方审核技能是辅助门控，法定审方仍在医院合理用药/处方点评系统。
4. **绕过编码质控。** 病案首页与结算清单的编码提交仍走病案/医保办流程。
5. **破坏审计追踪。** 任何建议必须带 span 或编码六字段出处；禁止无出处改写病历段落。
6. **患者数据出域。** 病历不得发到未授权的外部托管服务。本插件使用本地 MCP 与本地数据目录。

## 3. 与抽取/编码/审方的衔接

| 动作 | 允许 | 禁止 |
|---|---|---|
| 从出院记录抽取入院/出院诊断、手术、过敏、体征 | 是，须 span | 推断未写的并发症 |
| 将原文交给 `nhsa-coding` | 是，本地库 | 用美国 ICD-10-CM 填结算清单 |
| 将处方交给 `prescription-review` | 是，证据门控 | 无说明书证据宣称「无相互作用」 |
| 把结果贴回病程 | 仅当医院允许粘贴「建议」并人工确认 | 静默覆盖入院诊断、手术名称、过敏史 |
| 对接 FHIR / HL7 | 只读、用户配置的医院端点 | 指向未授权的公网 EHR |

## 4. 输出模板（评级约束检查）

```
【电子病历评级约束检查】
拟进行的操作：抽取 / 编码 / 审方辅助
是否写入 EMR：否（默认） / 是（须信息科授权文号）
是否替代诊断：否
是否替代药师审方：否
数据是否出域：否（本地 china-codes / drug-labels）
审计：抽取有 span；编码有 code_version/source；审方有说明书版本
风险：列出可能影响闭环或术语一致性的步骤（无则写「无」）
```
