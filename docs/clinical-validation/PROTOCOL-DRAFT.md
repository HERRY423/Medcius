# Medcius 查房前变化核对：临床验证方案草案

状态：DRAFT / 未批准执行 / 未注册研究。日期：2026-10-04（America/Los_Angeles）。

目标是检验准确性、医生工作负担及安全表现，而不是预设插件必然有益。当前新增工程能力不启动患者入组、真实资料导入、临床提示或 EHR 写回。尚未提供可核验的合作医院、数据授权、独立评审者或研究批准。

## 1. 冻结用途与责任

- 对象：住院查房前，医生核对过去 24/72 小时的资料与未闭环事项。
- 首期仅 patient-evolution-summary；交班、会诊、出院技能维持临床冻结。
- 产品输出：来源可定位的变化、记录修订、待办、数据缺口；不作自主诊疗。
- 对照：合作病区现行查房准备流程。比较相同任务边界与可获得数据。
- 医生负责临床判断；研究复核者评价固定版本输出；独立评审者建立参考标准。
- 研究复核签名仅证明谁签署了哪份评价，不等于原医院结果已确认、医嘱已执行或事实一定正确。

## 2. 可检查的工作流（当前已实现的部分）

授权只读来源 → 固定 as_of 与数据快照 → 输入/输出/算法哈希 → 静默归档与审计锚点 → 研究复核包 → 五轴逐条评价 → 待签署事件 → 可信登记密钥验签 → 保留评价、未评价条目与审计回读。

复核包保留来源清单、接口可用性、完整冻结输入与输出、资源与时间状态、规则包、数据缺口和失败。条目链接是导航候选，不被标为事实已验证。来源不匹配或派生条目保留 unresolved_or_derived，多版本链接保留多个候选。

五轴：source（出处）、time（时间）、state（状态）、missingness（缺失表达）、fact（事实准确性）。每轴只允许 supported / contradicted / uncertain / not_evaluated。无自由文本审计入口；签名绑定整个评价事件和固定复核包。

### 接口与权限

| 接口 | 用途 | 权限 |
|---|---|---|
| GET /api/v1/research/review-packet?case_id=… | 获取固定复核包 | 已认证 auditor 或 admin；绑定租户 |
| POST /api/v1/research/review/prepare | 创建评价事件，尚未签名 | 同时具有 physician 和研究访问角色 |
| POST /api/v1/research/review/confirm | 验证外部签署的信封并追加签收 | 同一复核人、同租户、已登记可信公钥 |
| GET /api/v1/research/review/status?case_id=…&event_id=… | 回读评价状态与未评价数量 | 研究访问角色；绑定病例和租户 |

请求方不能自报替换角色或病例来源。签名私钥不上传；由获批客户端/医院签名集成签署。普通 physician 不自动获得静默研究数据访问权。新增接口不是院端身份注册或执业资质认证。

prepare 请求需包含 case_id、packet_sha256 和 assessments；每条 assessment 包含 row_id、row_sha256 及全部五轴。confirm 包含 case_id、event_id、key_id、signature 和标准 signoff envelope。缺签名的 prepared 事件始终 pending_signature。签署 agree 表示确认记录了这些评价；条目本身仍可为 contradicted 或 uncertain。

当前没有双盲分发服务；共享研究角色可查看研究数据和审计。独立参考标准必须在分开的受控流程中先建立并冻结，不能宣称本接口已实现双盲。也没有将审计签署自动升级成临床证据的路径。

## 3. 分阶段研究计划（执行前批准）

### A. 工程与合成验收

覆盖错误患者/租户、未来和未知时间、报告更正/撤销、延迟入库、接口空结果与不可用、旧确认不能覆盖新版本、未复核条目、签名替换/重放、PHI 出口与归档重放。通过只支持相应工程行为。

### B. 获批回顾性准确性评价

由医院与研究负责人确定纳入/排除标准、连续抽样区间、病区范围、授权与去标识化边界。先冻结病例名册、软件/规则/模型版本、参考标准字段、评测指标和分析方案。开发数据与验证数据隔离；验证后修改版本须作为新版本重新评价。

两名具有相应资质、独立于开发过程的临床评审者先查看原始资料，在未看到插件输出时建立参考事实和关键待办清单。独立评价并保留分歧，由第三名评审者仲裁。不得只审核插件生成的条目，否则无法发现遗漏。

准确性至少分别报告：精确匹配事实、遗漏、错误解释、无来源新增、错误患者/时间/单位/极性、状态错误、未确认误闭环。事实匹配要求由批准方案定义；逐字匹配或签名不能替代事实评价。分母覆盖所有入组病例和参考事实；缺失、失败、弃答单独报告。

### C. 院内静默观察

在获批院内边界连续纳入，仍不向临床医生展示卡片或草稿。记录数据源覆盖、故障、版本冲突、输出完整性与时间延迟，确认真实接口行为。静默阶段无法证明医生使用后的效率或患者获益。

### D. 另行批准的医生使用对照研究

在准确性和工程安全达到经批准的门槛后，再制定对照设计。可考虑随机分配病例/医生/时段或交叉设计，但分配单位、顺序、记忆效应、学习效应、病区和医生聚类必须由统计负责人确认。

时间边界：从开始获取资料，到医生完成核对与记录。分别采集查找、阅读、证据核对、纠错、记录、等待；失败后的人工回退时间属于干预流程，不能删去。收集培训负担、错误信任、忽略提示、人工覆盖及可用性问题。

安全评价至少区分关键事实遗漏、错患者、错时间、错单位、错误闭环、近失事件和实际不良事件；确定观察窗口与独立归因流程。无观察不能记为零；零事件也不能证明安全。资料核对质量、过程安全与患者结局分别报告。

## 4. 统计与收益判定：待冻结项

不预设样本量，不使用合成记录估算临床收益。统计负责人须确定主要终点、最小有意义的节时幅度、准确性/安全容许差异、置信水平、检验功效、相关结构、失访与缺失处理、亚组、多重比较和中期停止规则。

项目既有“节省 90 秒”仅作为讨论候选；本草案不将其称为已注册或经临床论证的阈值。任何安全非劣效性必须有经批准的差异界值和统计分析，不能由两组错误计数大小决定。

当前 observations.mjs 仅汇总描述性观察：保留固定名册分母；校验事实计数；计算各环节总耗时、配对节时及完整病例节时；保留缺失与无安全观察状态。所有输入来源仍标 caller_reported_unverified，不计算推断性置信区间、因果获益或非劣效结论。哈希/签署事件编号字段不是独立核验。

## 5. 暂停、回滚与退出

错误患者/租户关联、未经授权的数据出口、来源或审计完整性破坏应停止该路径并交由批准的负责人调查。临床事件的严重程度、上报时间和具体停止界值须由院方批准。停用展示或连接器后回到既有人工流程；保留既有冻结记录和审计，不删证据、不降低检查标准。

本次代码回滚可撤去新增 research/review 路由及对应研究模块；既有只读静默捕获与审计格式不变。不要删除已产生的评价事件。当前安装缓存未自动更新，本次为源码变更。
