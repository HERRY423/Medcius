新增 **6 类 / 38 项**，全部检出。加上既有 engine-challenge 的 4 个错误输出对照，共 7 个评测入口具备负对照；两套报告身份仍分开，不合并样本量。

这不是独立临床金标准。shadow 的预测与标签仍为同源夹具；annotation 的逐字标记仍由输入声明，缺少原文认证；临床验证 batch01 为合成数据；公开参考用例与规则包仍可能同源。负对照证明量具能识别列明的错误，不能消除这些独立性限制。time-motion 的预设时间模型也没有因此变成实测观察。

## 实际修复的评分漏洞

1. 公开参考评测原先只核对预测为 flag/clear 的行：本应 flag/clear 却弃答的行可能被排除且不计失败。现在按全部预期记录配对评分，非预期弃答、缺失、重复和事实出处不匹配均失败；二分类统计明确限定为完整二分类对，不以其替代全样本结果。
2. 噪声评分原先允许字段 value 包含预期文字就抵消 span 缺失。现在 span_contains 必须在 span 字段命中。干净基线仍为 100%，combined 仍为 66.7%，未下调 65% 回归阈值。
3. 公开参考报告在读取本次输入前先写入 INCOMPLETE。失败后不能继续把上次成功文件当作本次结果；CLI 负例验证这一点。

新增检查已纳入 `run-all-checks.mjs`，并进入 [当前证据索引](CURRENT-EVIDENCE.md)。任一未检出的错误输出会使测试失败；未完成的对照报告先标 INCOMPLETE，不保留旧成功摘要。

## 生产规则包：可交接，但仍未批准

新增 [审核准备工具](../../scripts/prepare-rule-pack-review.mjs) 与 [负例测试](../../tests/test-rule-pack-review.mjs)。已生成的 [院方审核材料](../../out/rule-pack-review-11ac720a-8113-4ab7-9363-525d2200c13b/REVIEW.md) 包含：

- 原始 sandbox 候选副本，不改为 official/approved。
- 每组规则、单位/阈值/适用人群/来源/时限的核对要求。
- 绑定最终规则内容摘要的待签审核表；医院、批准人、日期、制度出处、回滚责任人未虚构。
- 机器可核对的准入缺口清单；区分文件字节匹配与签名真实性。

校验覆盖内容变更、批准附件篡改、附件路径越界、院区不匹配、复审过期。即使合成测试填上 approved、批准人及正确附件摘要，也只能达到“技术前提齐备”，机构授权仍为 NOT_VERIFIED，准入仍阻断。此工具不替代实际生产加载器或院方签署系统，不自动安装或激活规则包。

下一步由院方责任人提供正式制度/规则、明确医院适用范围、核验最终内容并具名批准；随后在受控部署流程中核验身份、签署和激活。本地编码无法完成这项外部事实。**生产可用院方批准规则包仍为 0。**
