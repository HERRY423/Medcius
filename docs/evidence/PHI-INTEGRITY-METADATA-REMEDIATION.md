# PHI 扫描与完整性元数据：确定性复现、修复及验证

日期：2026-10-07。范围：本地工程、合成资料、隔离审计库；未读取医院历史审计库或部署到医院。

## 复现结论

截图指出的摘要损坏可确定性复现。固定输入 `synthetic-integrity-regression-111` 的真实 SHA-256 为：

```text
3806fb08ee3d39f323cff3e1dee25cd3b6e8bcd0a7ef6a2132e9e13093590581
```

旧的通用字符串脱敏路径把末尾数字识别为手机号，64 字符变成 79 字符。相同问题也可能由座机、身份证、银行卡规则触发。只有长度断言不足以验证完整性；修复后的测试比较完整字节、重新计算摘要，并执行密码学验签。

根因是把完整性元数据当作自由文本扫描，以及多层出口再次递归扫描时丢失字段语义。手机正则的数字边界在自由文本中仍有必要：直接排除所有十六进制字母，会漏掉 `tel13912345678x` 一类含真实号码的文本。本次保留自由文本检测，修复结构化边界。

## 实现

- `servers/shared/integrity-metadata.mjs` 定义明确字段名与严格编码规则。已登记的 SHA-256 字段必须是完整 64 位十六进制字符串；不使用任意 `*hash`/`*sha256` 后缀豁免，不豁免字段下面的整个对象或数组。
- 同一规则用于模型安全副本、结构化 PHI 断言、来源文本扫描和 MCP 出口，避免“先保留、后误删”或检测与转换不一致。
- MCP 的普通结果、`structuredContent`、`_meta`、文本中的 JSON 对象和嵌套 JSON 均保留字段语义。已经安全的 JSON 字符串保留原字节，包括空白和转义，避免重新序列化改变签名材料。
- ECDSA P-256 签名只在算法声明匹配、Base64 规范且 DER 整数结构合法时按完整性元数据保留；公钥只保留可解析的规范 PUBLIC KEY PEM。格式识别不证明签名有效，更不证明临床身份；实际信任仍由既有验签、注册密钥和授权链建立。
- 身份字段继续先执行 PHI 保护。未知字段、普通病历文本、字段名中的身份信息、错误长度、非摘要内容和相邻敏感信息继续扫描。
- 来源快照、交接事件、出院文档、会诊诉求及合成评估扫描结构化内容，不先将所有内容压平成一个字符串。冻结研究记录仍先重新计算摘要验证完整性，再做结构化隐私检查。
- **审计入口保留更严格的原有策略**：调用者不能仅凭 `record_sha256` 等字段名放行号码片段；仍使用既有摘要字节编码，普通文本照常拒绝。审计存储生成的输出摘要则在出口原样保留。没有改写审计表、重新链接旧链或取消签名/篡改校验。

## 消除时间偶发性

`getCardiologyMultiSourceFeeds({ now })` 让病区和多源资料共享同一可注入时刻。医院 Agent 适配器测试固定 `as_of` 和资料生成时间为 `2026-10-06T10:00:00.000Z`，避免毫秒变化引入不可复现的摘要。

固定时钟不是唯一修复：新测试仍覆盖 1,024 个不同固定输入生成的真实摘要，并校验修复前必然命中的反例。临床来源时间缺失仍保持未知；测试时钟不被用来补全患者事实。

## 已生成历史产物如何处理

这次修复不能证明以前生成的每份产物都完整，也不自动修复已损坏的摘要。对需要使用的历史报告，应在获授权的本地环境中：

1. 保留原始记录，检查摘要字段是否仍符合其编码契约，是否含替换标记。
2. 从原始规范化载荷重新计算摘要，对照原有签名、审计行和可信检查点；长度正确也不能代替这一步。
3. 若只是在展示/传输副本中损坏，使用原始完整来源重新导出并保留恢复记录。
4. 若原始签名材料缺失或无法匹配，标记为不可验证；不得填造摘要、补签来假装恢复原始证明，也不得修改追加式审计链。
