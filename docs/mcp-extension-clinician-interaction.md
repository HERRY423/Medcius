# 从 MCP Extensions 到医生可控的资料核对

本次实现将“看一份报告”扩展为“选择证据、说明疑点、限定问题范围、明确提交”。Medcius 的临床输出权限没有扩大；新增 MCP 面板只接受内置合成资料。工作台参考适配器仍受医院静默试点门禁约束。

## 上游阅读范围与判断

2026-10-07 阅读了 OpenAI `mcp-extensions` 的 README、完整协议中的入口/资源/上下文/消息/设置/提及部分，以及 TypeScript App transport、message、model-context 的实现。固定来源版本：[`0ba30cd5e3aa17265685969508e0ca7e39011a3a`](https://github.com/openai/mcp-extensions/tree/0ba30cd5e3aa17265685969508e0ca7e39011a3a)。[协议原文](https://github.com/openai/mcp-extensions/blob/0ba30cd5e3aa17265685969508e0ca7e39011a3a/docs/spec.md)。

它在 MCP Apps 基础上增加宿主交互契约，不提供临床有效性、人员认证或通用医院界面。对 Medcius 最有价值的是让医生主动打开工具并提供精确范围，减少反复描述和整份资料无差别进入对话。

| 上游能力 | 本次选择 | 原因与边界 |
|---|---|---|
| 全局/会话入口 | 可选工具声明两个入口，空参数可打开合成示例 | 医生可以主动打开面板；是否显示、固定入口由宿主决定 |
| MCP Apps HTML resource | 包内静态 `ui://` 资源、桌面/窄屏布局 | 不读取任意本地路径；不加载远程脚本或外部资源 |
| 首次工具结果 | 直接消费初次结果，不重复调用入口工具 | 避免重建报告、覆盖正在阅读的版本 |
| `ui/update-model-context` | 明确点击才附加选中条目 | 不自动发送整份患者报告；内容变化先清除旧上下文；处理宿主删除附件通知 |
| `ui/message` | 预览后点击立即提交当前问题 | 使用当前会话；区分发送回执与实际复核结果；未知结果不自动重发 |
| 能力协商 | 检查宿主文字上下文/消息能力，扩展参数按能力添加 | 不支持时保留阅读能力并禁用对应按钮，不能显示假成功 |
| 文件扩展名入口/文件更新 | 本次不启用 | 宿主资源 URI 不是本地文件路径；真实病历文件需独立数据边界、来源授权和版本控制 |
| 资源提及与检索 | 本次不建立患者列表或自动检索 | 防止跨患者/跨租户披露；未来需服务器端授权与受限查询 |
| 结构化设置 | 本次仅提供本页筛选 | 安全阈值、规则包与临床权限不能作为个人设置随意改变 |

采用原生 JSON-RPC 实现所需的有限 App 契约，与仓库现有零依赖 MCP transport 一致。没有引入上游 SDK 依赖，也没有声称实现扩展的全部协议。后续扩大文件、订阅或设置能力时，应重新评估官方 SDK 与宿主支持情况。

## 医生交互与状态

1. 阅读来源：每项展示资源标识、版本、时间、原文定位与定位核验状态。没有证据的位置明确为空/未知；来源关联不等于事实正确。
2. 选择重点：最多 12 项；按全部、未读、存疑、暂缓、我的重点筛选。选择只限制核对请求，不从原报告删除未选择的风险或资料。
3. 表达判断：已读、存疑、暂缓、撤销标记。存疑必须区分来源、时间、状态、缺失或事实；“已读”不能提升事实支持等级。
4. 补充问题：保存前经过 PHI Guard。输入框保留未保存问题；未保存的改动不能悄悄进入已预览请求。启发式扫描不保证识别无标签人名，真实患者数据仍禁止进入实验面板。
5. 预览与提交：完整预览所选内容，分别执行附加上下文与发送消息。模型收到来源材料时，明确把材料视为数据，不能把资料中的指令当作医生指令。
6. 暂停与恢复：暂停本页操作，不撤回已发送消息，也不能保证暂停宿主模型。重新准备范围会使旧请求失效。

阅读草稿与现有研究签名链路分开：没有生成医师签名、关闭高风险随访、记作临床确认或回写 EHR。未认证的 App-only 调用不能成为“某医生做过某决定”的证据。

## 一致性、隔离与故障

- 共享 `ClinicianReviewSessions` 绑定服务器生成的报告、患者/就诊上下文、条目内容与修订号；拒绝旧版本、错条目或跨身份/租户访问。
- 保存请求带唯一标识；重复同一请求返回当前状态，复用标识修改内容会拒绝。发送超时按“结果未知”处理。
- 草稿固定 30 分钟过期，最多 100 会话、每会话 500 操作；没有持久保存承诺。
- 服务器仅保留脱敏问题，原始问题不进入审计、日志或请求缓存；请求恢复缓存只有摘要。摘要采用字母编码，避免隐私扫描误改内部标识；未绕过 PHI 扫描。
- 工作台沿用登录、权限与静默/生产门禁。切换患者/任务、刷新或迟到请求不能恢复旧报告的草稿。
- MCP 面板只使用固定合成病例，无患者导入、无病历写入、无 FHIR 凭据。可选配置见 [接入说明](../integrations/mcp-review-app/README.md)，未写入默认产品 manifest。
- App 只接收父窗口 JSON-RPC 消息，设置请求超时；资源服务只读取注册的包内静态 HTML。资源 CSP 不开放外部连接。

## 验证与剩余工作

自动化测试覆盖领域状态、PHI 出口后的完整读写、角色/租户隔离、修订冲突、重复请求、过期、工作台迟到响应、入口元数据、伪造窗口消息、能力缺失、上下文撤销、消息失败，以及真实 stdio `initialize/resources/tools` 通道。

本轮最终结果：21 项定向测试通过；完整门禁 75 步骤完成（62 项检查通过、13 项报告生成），0 失败。缺失的外部插件校验器与证据范围见 [本地验证记录](evidence/MCP-REVIEW-INTERACTION-VALIDATION.md)。

浏览器检查使用本地模拟宿主，验证桌面/窄屏、选中条目、存疑、补充问题、上下文附加与明确提交。它没有调用模型，也不构成原生宿主验收。结果保存在 `out/review-app/browser-check.json`，测试脚本为 `scripts/verify-review-app-browser.mjs`。

证据状态必须保持分开：

| 证据层 | 本次能证明什么 |
|---|---|
| 工程/协议回归 | 本地实现及规定失败路径的行为，见完整门禁记录 |
| 合成交互 | 内置病例与模拟宿主中的操作闭环 |
| 原生 Codex/ChatGPT 宿主 | **NOT_RUN**；需真实宿主中安装、显示、上下文与消息验收 |
| 医生可用性/时间收益 | **NOT_ESTABLISHED**；需医生任务测试与独立测量 |
| 临床有效性与医院交付 | **NOT_ESTABLISHED / BLOCKED**；不因界面改进解除规则包、独立验证、院方批准等条件 |

下一阶段应先在指定开发宿主完成原生验收，再组织医生使用合成病例做观察性任务测试：能否区分旧结果与更正结果、能否发现缺失、核对请求是否范围正确、暂停/未知状态是否理解一致。医院真实使用还需要批准的数据部署边界、真实目录身份、持久审计与研究复核链路的独立接入；本次没有假定这些条件已满足。
