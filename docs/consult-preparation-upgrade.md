# 会诊前资料整理：诉求驱动的同快照专科视图

本次依据“深度审阅升级”完整对话复核本地实现，范围是会诊资料寻找、整理和回源核查。只读工程路径仍保留 P0-FROZEN；没有开放真实患者临床使用、自动会诊意见或 EHR 写回。

## 本次修复的实际问题

| 原行为 | 当前行为 |
|---|---|
| 无科室/诉求时引擎补通用会诊目的 | 引擎、宿主与 HTTP 入口均要求明确科室和诉求 |
| 用专科关键词筛选，与诉求没有联系 | 明示关注词及从诉求匹配的词优先排序，显示纳入原因；不宣称语义理解或已验证临床相关性 |
| 病历只截取前 120 字 | 定位匹配处，返回原文摘录及 UTF-16 起止位置 |
| 缺报告结论补“未见明显异常” | 保持 null / 结论未提供 |
| 所有非 final 报告都算待出 | 分别保留初步、未知、取消、录入错误与更正状态 |
| 所有药物算当前用药，缺字段补 po/qd | 只有来源明确 active 的医嘱进入活动组；未知状态独立列示，途径/频次不补造 |
| 各次整理独立取数、摘要没有绑定内容 | 快照构建一次，专科视图共用快照及截止时间；内容摘要绑定快照和资料包 |
| 报告展开技术键值树 | 专门的会诊阅读顺序，逐项展开来源；技术字段保留在证据层 |

## 医师需要完成的交互

1. 沿用宿主授权的患者与就诊上下文；填写目标专科与明确诉求。具体问题、关注资料词可选。
2. 看诉求、资料截止时间与具体缺口，浏览相关病程、检验、报告、用药资料。
3. 点击“查看原始依据”核对该记录。普通组先显示五条，剩余可展开；来源危急标记不受此数量限制。
4. 多专科会诊通过同一个快照派生不同视图；刷新数据是新快照，不能覆盖旧资料包的身份。

提供本地合成双专科演示：运行 `node scripts/demo-consult-preparation.mjs`，打开 `out/consult-preparation/synthetic-preview.html`。演示复用实际参考工作台的渲染函数；页面切换专科不会读取网络。

## 插件和宿主契约

```javascript
const snapshot = ConsultPreparationEngine.createSnapshot({
  context: { tenant_id, patient_id, encounter_id },
  patient, encounter, asOf,
  notes, observations, diagnosticReports, medications, orders, nursing,
  allergies, sourceAvailability,
});
const result = ConsultPreparationEngine.prepareConsultViews({
  snapshot,
  consultRequests: [
    { department: "肾内科", purpose: "整理血钾变化资料", focus_terms: ["血钾"] },
    { department: "心内科", purpose: "整理心衰相关资料", focus_terms: ["心衰", "BNP"] },
  ],
});
```

宿主适配器支持 `consultRequests` 批量视图；兼容单个 `consultRequest`。HTTP 参考入口继续生成单专科视图，使用相同快照构建器并绑定认证租户。此改动没有把全项目其他工作流迁移到会诊快照。

快照对象不可变，派生视图仅接受构建器创建的对象。跨进程回放应从冻结源输入重新构建；不能把任意 JSON 当成已经验证的快照。摘要是完整性标识，不是授权凭据或临床正确性证明。

共享已有记录生命周期解析器，按记录身份解析版本，不把同项目独立测量合并。缺来源 ID/时间、冲突、被替代、未来记录不进入当前资料。未来源内容不在完整证据中展开。病历摘录保留原句，不推断病因或回答会诊问题。

护理原始体温、生命体征、尿量与出入量字段可按诉求纳入，并保留记录来源和时间。缺少记录区间时不计算“近 24 小时总量”，不计算风险评分；明确记录的零值与缺失字段分开处理。

来源记录经过 PHI Guard；结构化身份被封存，带识别信息的记录自由文本拒绝进入输出。内容摘要明确标记基于经过保护的来源记录。FHIR 资源 ID/来源记录定位符由宿主解析；当前参考界面展开本次快照里的来源，尚未证明能直接跳转任何医院的源系统。

## 已知边界与下一步证据

- 专科词汇是确定性检索词库，尚无独立专科医师金标准。可能漏掉同义词或只有隐含相关性的资料；无模板、无法映射诉求时提示缺口，并提供其他资料入口。
- 记录级患者/就诊字段缺失的合成资料仅绑定资料包上下文，并明确标记 `feed_context`；不宣称完成真实来源归属验证。
- 来源可用、成功为空、不可用和完整性未知分别保留。未提供接口覆盖不能推出“没有相关资料”。
- 过敏史当前简单输入缺少资源/时间证明时只提示待核对。完整 AllergyIntolerance 溯源映射仍是后续接入工作。
- 参考范围缺失不推断正常/异常。医嘱不等于实际给药，浏览不等于专业确认。
- 检查医嘱与结果的跨资源关联尚需来源明确映射，当前标记关联/执行待核对，不凭同名检查自动闭环。
- 工作台仍为工程参考适配器；真实院内宿主接线、患者切换、SSO、来源深链接和临床可用性需单独验收。
