# 交接班准备：变化、待跟进与医生责任事件

本次完成工程与合成路径改造。交接班仍为 P0-FROZEN，没有开放 HIS/SSO 临床使用、持久化接班签名或 EHR 写回。

## 用户看到的变化

先看资料截止时间、交接状态，再看变化/更正、待跟进、来源医嘱和交班医生原话预案。病程、护理记录和事件历史按需展开，原始资料就在对应条目下。

| 旧行为 | 改进后 |
|---|---|
| 根据诊断或血钾自动生成医学应急预案 | 只显示经宿主核验的医生原话，包括触发条件、提供者、时间与事件 ID |
| 按床号猜特级护理，缺数据写“平稳”或“无特殊操作” | 不推断稳定性/护理级别，缺失明确为未知 |
| 文本末尾默认出现双方“签字确认” | 提出转交、接班确认、拒接、撤回各为独立来源事件 |
| 不绑定具体资料版本 | 接班确认引用提出转交事件及精确资料包摘要；资料或预案变化使旧确认失效 |
| 交接完成可能被理解为任务完成 | 接班确认不关闭检验结果复核、待跟进事项，也不表示已执行预案 |
| 会诊和交班各自解析资料 | 共用不可变 `patient-source-snapshot`；会诊旧接口保留兼容导出 |

## 两种截止时间

- `as_of`：冻结来源资料的截止时间。所有当前资料、变化与跟进状态从同一快照派生。
- `events_as_of`：读取医生交接事件的截止时间，可晚于资料截止时间。准备后的确认可以引用原资料包，不能暗中刷新临床资料。
- `window_start`：变化窗口起点，核心引擎必须显式提供。宿主参考适配器默认取资料截止前 24 小时并在输出中显示。
- 没有前次查看快照时，不声称“自上次查看以来新增”。未来、冲突、缺少来源/时间记录不进入当前事实。

## 事件与责任语义

事件公共字段：`event_id/type/tenant_id/patient_id/encounter_id/handover_id/actor_id/occurred_at`。

| 类型 | 额外字段 | 允许的提供者 |
|---|---|---|
| `plan_recorded` | `plan_id/action_text`，可选 `trigger_text`；修订引用 `supersedes_event_id` | 指定交班医生 |
| `plan_withdrawn` | `plan_id/supersedes_event_id` | 指定交班医生 |
| `transfer_proposed` | `packet_digest` | 指定交班医生 |
| `transfer_accepted` / `transfer_declined` | `packet_digest/target_event_id` 引用提出转交事件 | 指定接班医生 |
| `transfer_withdrawn` | 引用当前提出转交事件及其摘要 | 指定交班医生 |
| `acceptance_revoked` | 引用接班确认事件及其摘要 | 指定接班医生 |

事件 ID 相同、内容相同的重复交付被合并；同 ID 不同内容拒绝。同一状态流同一时刻的多个迁移无法确定先后则拒绝。前序缺失、错患者/租户/就诊/班次、错人、未来事件、PHI 或来源核验失败均拒绝。输入数组排序不构成事件发生顺序。

资料包摘要包含来源快照、窗口、双方身份、当前提供的预案、变化与跟进状态；不包含接班确认本身，避免签名循环。预案修订或来源资料变化后，旧提出转交/确认保留历史，状态为 `requires_reconfirmation`。

`accepted_in_source` 只表示所提供来源历史中存在有效的接班确认。**单条签名不足以证明后续没有撤回。** `current_responsible_doctor_id` 还必须得到完整事件历史核验；缺少此核验时为 null。报告中的“责任”是来源报告的状态，不是本插件变更了医院责任登记。

## 宿主接线

1. 用 `ShiftHandoverEngine.createSnapshot` 或共享快照构建器固定已授权源资料；可将同一对象交给会诊引擎。
2. 调用 `analyzePatientHandover`，传入 `snapshot/windowStart/eventsAsOf/handoverContext`。
3. 提供只读的 `handoverEvents` 和部署侧同步 `verifyHandoverEvent`。核验者负责真正的来源签名、操作者身份、权限、撤销和上下文绑定。JSON 自报的 `verified` 没有任何效力。
4. 需要来源所报告的当前责任归属时，部署侧还必须提供 `verifyHandoverHistory`，验证 `history_digest/context/handover_context/events_as_of` 与完整的权威事件流或可信清单一致。不能用每条签名通过代替完整性核验。
5. HTTP 工程参考入口通过部署代码注入 `setWorkstationHandoverEventVerifier(eventVerifier, historyVerifier)`；不接受请求注册核验器。未配置时可整理来源资料，但拒绝宣称经核验的人为事件。

本轮不新增事件写入服务或签名按钮。宿主仍负责真实医生操作、持久化、审计、身份认证与权限控制；没有把来源事件输入当成已完成 EHR 写回。

## 共享逻辑修复

复用已有生命周期解析与高风险跟进模块，保留其来源覆盖/未知状态。来源仍用 `final`、但版本解析已检测到内容更正时，交班跟进继承“更正”语义，不能重新解释为未经更正的新结果。

同时修正共享跟进模块：`acknowledged:false` 与确认时间并存时保留冲突/未知，不关闭事项。来源报告的危急标记使用同一判断函数，避免评估区与待跟进区分叉。
