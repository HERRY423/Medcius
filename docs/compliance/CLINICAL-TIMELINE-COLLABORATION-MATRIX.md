# Medcius 临床真实时间线协同体系矩阵 (Clinical Timeline Collaboration Matrix)

> **版本**：`0.2.0-pilot`  
> **定位**：一线临床医生全天真实工作流时间线下的 **Agent - 插件 - 医生** 协同分工与安全边界  
> **核心原则**：**把「极致」落到医生真实时间线，而不是功能清单**

---

## 一、 核心分工体系：三元协同架构 (The Tripartite Harmony)

Medcius 拒绝将产品做成臃肿的功能清单或脱离一线节奏的模型聊天室。整个系统由三方紧密咬合、职责边界钉死：

```text
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                              【临床三元协同闭环】                                      │
├──────────────────────────┬─────────────────────────────┬───────────────────────────────┤
│ 角色                     │ 核心价值                    │ 严禁越权行为                  │
├──────────────────────────┼─────────────────────────────┼───────────────────────────────┤
│ 1. Host Agent (宿主智能体)│ 降低交互摩擦                │ 🚨 严禁自主临床决策；          │
│                          │ • 意图识别与技能路由        │ 🚨 严禁凭空编造临床印象；      │
│                          │ • 对话式收集上下文信封      │ 🚨 严禁向云端贴入原始病历明文。│
│                          │ • SBAR 结构化表达与 L2/L3 讲解│                               │
├──────────────────────────┼─────────────────────────────┼───────────────────────────────┤
│ 2. Medcius Plugin (插件) │ 降低信息摩擦                │ 🚨 严禁自主诊断与治疗建议；    │
│                          │ • 异构多源数据归一与对齐    │ 🚨 严禁不带证据 span 编造事实；│
│                          │ • 确定性精确代数与时序计算  │ 🚨 严禁暴露写工具与自动回写。  │
│                          │ • 严格只读、失败关闭与审计链│                               │
├──────────────────────────┼─────────────────────────────┼───────────────────────────────┤
│ 3. Clinician (执业医师)  │ 降低决策摩擦 (最终决策者)   │ ⚠️ 不做盲目信任的签字工具人； │
│                          │ • 扫读 L1/L2 分层视图       │ ⚠️ 必须核实 L3 原始证据与床旁；│
│                          │ • 点选可疑原文 Span 溯源    │ ⚠️ 独立在原生 EMR 中加盖 CA。 │
│                          │ • 决定查房路线、处置与签章  │                               │
└──────────────────────────┴─────────────────────────────┴───────────────────────────────┘
```

> ⚠️ **反模式警示 (The Misalignment Anti-Pattern)**：  
> 让 Agent 做决策、让插件做聊天、让医生当校对员却看不到原文——任何一处错位都会彻底破坏临床安全！

## 二、 四大核心临床时间线落地场景

### 1. 晨查房前（旗舰工作流 - Pre-Round Patient Evolution）

* **医生真实瓶颈**：  
  晨会或查房前需在 15-20 分钟内快速评估病区 8–15 张床位的患者。最耗时的不是「理解病情」，而是在脑海中把护理记录单（体温/出入量）、LIS 检验（危急值/电解质/肌酐）、PACS 报告与 HIS 医嘱逐一对齐。
* **Host Agent 动作**：  
  识别医生「查房摘要」意图，自然交互确认病区患者与时间窗（24h/72h），调取 **L1 走廊胶囊 (~3s)** 给出查房巡视路线工作流提示。
* **Medcius 插件动作**：  
  通过 `ReadOnlyHospitalDataBridge` 拉取 NIS/LIS/PACS/HIS 数据；执行纯数学计算（$T_{\max}, T_{\min}$、24h 净出入量代数和、eGFR、抗菌药使用天数）；执行高风险生命周期追踪（ordered $\rightarrow$ scheduled $\rightarrow$ resulted $\rightarrow$ acknowledged），显式标出资料缺口（过敏史/肌酐/规则包）。
* **执业医生动作**：  
  扫视 L1 胶囊确定优先床位（如 08床 出现血钾 2.4 mmol/L 危急值），阅读 L2 四区块卡片，按需点击 L3 原文 Span 溯源，带着明确问题走向床旁。
* **核心放大价值**：  
  **放大工作记忆与遗漏拦截（Working Memory & Omission Interception）**，绝不代替医生做诊断。

---

### 2. 交接班（Shift Handover - SBAR/I-PASS）

* **医生真实瓶颈**：  
  白班与夜班口头交接容易遗漏夜间生命体征极值（如凌晨一过性低血压或发热）、危急值闭环状态以及次日待复查的特殊医嘱。
* **Host Agent 动作**：  
  以标准化 SBAR（现状-背景-评估-建议）/ I-PASS 语法组织汇报对话，辅助医生梳理交班要点。
* **Medcius 插件动作**：  
  自动从 NIS/LIS/HIS 抽提夜间体征极值、未出结果检验、待执行特殊医嘱；并在技能目录与元数据中**显式声明：禁止替代床旁面对面口头交接**。
* **执业医生动作**：  
  对照结构化备忘，当面与接班医生逐床确认重点患者夜间变化与次日待办。
* **核心放大价值**：  
  **放大结构化备忘（Structured Memorandum）**；面对面床旁交接依然是临床金标准。

---

### 3. 会诊 / MDT（Consultation / MDT Dossier）

* **医生真实瓶颈**：  
  受邀专科医生被数十页冗长、无关的日常病程记录淹没，找不到申请科室的真正核心诉求与关键专科指标。
* **Host Agent 动作**：  
  抓取会诊科室与具体会诊诉求；**若缺少明确诉求，立即 Fail-Closed 提示补充，严禁泛化发散**。
* **Medcius 插件动作**：  
  按专科规则包过滤核心时间轴、未出细菌培养/病理报告、当前相关用药与靶器官功能；生成高信噪比的《专科会诊资料包》。
* **执业医生动作**：  
  受邀专科专家快速掌握焦点事实，专注进行专科查体与鉴别诊断，在原生 EMR 中书写会诊意见。
* **核心放大价值**：  
  **放大信噪比（Signal-to-Noise Ratio）**；插件绝不会诊代写医疗意见。

---

### 4. 出院日（Discharge Day - Safety & Completeness Audit）

* **医生真实瓶颈**：  
  出院当天事务繁杂，容易漏看未归病理报告、静脉抗生素转口服衔接断层、出院随访未约，或将患者医保报销/费用问题误以为「一切正常」。
* **Host Agent 动作**：  
  引导医生完成交互式出院安全核对清单对话。
* **Medcius 插件动作**：  
  核对全病程闭环状态（病理/培养）；比对住院用药与出院带药；原样呈现费用记录（严格遵守：`Coverage ≠ 已报销`，`费用估算 ≠ 最终结算账单`）。
* **执业医生动作**：  
  根据核对清单排除出院安全盲区，确认患者用药宣教与复诊计划，最终签发出院医嘱。
* **核心放大价值**：  
  **放大安全缺口可见性（Safety Gap Visibility）**；出院决定权完全属于主管医师。

## 三、 三层时间预算披露模型 (Staged Progressive Views)

为了与病区医生的真实物理时间预算深度对齐，Medcius 拒绝提供冗长单一的大段总结，而是输出严格的三层披露视图：

│ 层级                │ 时间预算   │ 内容呈现                              │ 驱动来源    │
├─────────────────────┼────────────┼───────────────────────────────────────┼─────────────┤

## 四、 监管合规与工程守卫承诺

1. **确定性双轨制**：  
   硬规则、极值、代数和、高风险阈值由插件引擎及经审批的医院专科规则包计算；LLM 仅用于抽取实体与渲染医生可读语句，严禁 LLM 进行临床诊断或臆测事实。
2. **只读隔离与禁止自动回写**：  
   Medcius 仅通过 `readPatient` 只读接口连接医院数据；生成的所有草稿标记 `write_back_blocked: true`，严禁任何非人工确认的 EHR 自动写回。
3. **PHI 出口强防护与哈希链审计**：  
   数据流出院内前置机/连接器前必须通过 PHI Guard 假名化脱敏；所有系统交互进入本地 Append-Only SHA-256 不可篡改审计链。
