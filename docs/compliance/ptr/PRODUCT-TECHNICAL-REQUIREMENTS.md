# 医疗器械产品技术要求（送审稿）(PRODUCT-TECHNICAL-REQUIREMENTS)

> **产品名称**：住院临床工作流数据辅助整理软件  
> **产品型号/规格**：Medcius Plugin Edition (v0.2.0-pilot)  
> **编制依据**：国家药品监督管理局《医疗器械产品技术要求编写指导原则》、GB/T 25000.51-2016《就绪可用软件产品(RUSP)的质量要求和测试细则》、GB/T 42062-2022。

---

## 1. 产品型号/规格及其划分说明

- **产品名称**：住院临床工作流数据辅助整理软件
- **软件发布版本**：`v0.2`；**软件完整版本**：`v0.2.0-pilot.20260828`
- **运行环境要求**：
  - **服务器端**：Linux / Windows Server，Node.js 运行时环境（≥ v20.0），支持 mTLS 双向认证；
  - **客户端/宿主 Agent**：支持 Model Context Protocol (MCP) 规范的临床医生工作台宿主（Codex、Trae、CodeBuddy 或医院定制化 Agent）；
  - **网络环境**：医院局域网内网隔离环境，HTTPS / TLS 1.3 传输加密。

## 2. 性能指标与要求

### 2.1 软件功能性要求 (Functionality)
1. **查房前患者演变摘要整理功能**：
   - 能够从医院病程记录、LIS 检验、NIS 体征及 HIS 医嘱中，自动提取过去 24/72 小时的临床事实；
   - 能够确定性计算体温极值、血氧极值、出入量代数和及生化指标演变差值（$\Delta$）；
   - 输出事实必须提供原始病程记录 Span 字符偏移或 FHIR 资源引用，严禁生成未在原文中出现的虚构词句。
2. **临床交接班 SBAR 整理功能**：
   - 支持按照现状（Situation）、背景（Background）、评估（Assessment）、建议（Recommendation）结构化归纳病区重点患者；
   - 能够自动归集夜间危急值与未闭环医嘱。
3. **专科会诊前资料包整理功能**：
   - 能够按专科诉求重构时间轴，聚合跨病程记录、检验演变与未回报检查。
4. **出院资料完整性核对功能**：
   - 能够核对关键检查检验报告是否出具终末结果、出院带药医嘱是否完整、过敏史等安全要素是否存在缺失。
5. **只读数据连接与防写回控制**：
   - 仅支持通过 HTTP GET 或只读接口读取数据，系统底层坚决不提供任何 `create` / `update` / `delete` 数据写回能力。

### 2.2 性能效率要求 (Performance Efficiency)
1. **单病案分析响应时间**：在标准测试硬件配置下，单份 24 小时住院患者全量多源数据处理与摘要生成耗时应 $\le 1000\text{ ms}$（毫秒）；
2. **冷启动与加载耗时**：技能目录与规则包解析加载时间应 $\le 500\text{ ms}$；
3. **并发处理能力**：支持单病区同时处理不少于 20 张床位的数据请求，不发生内存溢出或响应挂起。

### 2.3 易用性与人因安全 (Usability & Safety)
1. **证据高亮回溯**：点击任意抽取事实均能准确定位病历原文段落；
2. **缺口显式提醒**：当患者过敏史、肾功能基线等关键信息缺失时，必须显式以警告标识展示，不得默认填补虚假数据；
3. **人工责任闭环**：生成的任何文书草稿均需医师手动勾选与核对后方可采纳。

### 2.4 可靠性与容错能力 (Reliability & Fault-Tolerance)
1. **缺失上下文失败关闭 (Fail-Closed)**：当就诊标识、租户标识、患者标识或参考范围缺失时，系统必须拒绝生成推断并安全退出；
2. **抗干扰性**：输入包含乱码或格式畸形的病历文本时，系统应能捕获异常并跳过错误段落，不引起进程崩溃。

### 2.5 数据安全与网络安全要求 (Security & Data Protection)
1. **敏感个人信息脱敏**：患者姓名、身份证号、手机号等直接标识符在进入模型上下文前必须实施 100% 假名化或脱敏；
2. **传输加密**：支持 mTLS 证书双向认证与 TLS 1.3 传输加密；
3. **不可篡改审计**：操作与事件必须写入本地追加式 SHA-256 哈希链，支持链条完整性校验。

## 3. 检验方法 (Test Methods)

| 序号 | 检验项目 | 对应条款 | 检验方法与判定准则 |
|---|---|---|---|
| **1** | 查房演变整理与 Span 绑定 | §2.1.1 | 运行 `tests/test-preround-summary.mjs`，比对提取事实与原文 Span，要求匹配率 100%，无虚构事实。 |
| **2** | SBAR 交接班功能 | §2.1.2 | 运行 `tests/test-shift-handover.mjs`，验证 SBAR 结构四要素完整输出。 |
| **3** | 专科会诊资料整理 | §2.1.3 | 运行 `tests/test-consult-preparation.mjs`，验证专科时间轴重构正确。 |
| **4** | 出院核对与安全缺口 | §2.1.4 | 运行 `tests/test-discharge-readiness.mjs`，验证缺口正确报警。 |
| **5** | 只读接口安全隔离 | §2.1.5 | 运行 `tests/test-real-connectors.mjs`，尝试注入写方法，验证系统强制抛出拒绝异常。 |
| **6** | 性能基线与响应耗时 | §2.2.1 | 运行 `plugins/medcius/evals/performance-baseline/bench.mjs`，验证耗时全部在性能预算以内。 |
| **7** | 缺失要素失败关闭 | §2.4.1 | 运行 `tests/test-clinical-safety-rules.mjs`，验证非法/缺失参数时立即触发 Fail-Closed。 |
| **8** | PHI 脱敏与防泄漏 | §2.5.1 | 运行 `tests/test-negative-leakage.mjs`，验证敏感字段 100% 被捕获或假名化。 |
| **9** | 审计链防篡改校验 | §2.5.3 | 运行 `tests/test-security.mjs`，验证篡改历史记录后校验器能准确报错。 |
| **10** | 全要素自动化回归 | §2.1-§2.5 | 运行 `node scripts/run-all-checks.mjs`，37 项测试必须全部呈现 `[PASS]` 状态。 |
