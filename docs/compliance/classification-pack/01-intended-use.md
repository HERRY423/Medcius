# 01 预期用途说明书（草案）

> 按《人工智能医用软件产品分类界定指导原则》（2021-47号）与《医疗器械分类目录》（2017-104号，子目录21）撰写。需法规顾问终审。

## 1. 产品名称与边界

**Medcius** — 中国医院场景的 **信息系统辅助工具**，支持三项功能：

1. 医保编码辅助（`nhsa-coding`）：医保版ICD-10 / 医保版手术操作分类的查询与校验，六字段出处
2. 处方审核辅助（`prescription-review`）：证据门控的合理用药一致性比对，输出四态 PASS/FLAG/INSUFFICIENT_DATA/REQUIRES_PHARMACIST_REVIEW
3. 病历结构化抽取（`clinical-note-extract`）：中国住院 schema 的原文抽取，不诊断、不编码

**不包含**：诊断决策、鉴别诊断、治疗方案推荐、DRG/DIP分组、医保交易报文生成。

> 上述边界与 `README.md:3` / `SAMD-PATHWAY.md:15-18` 一致，是分类论证的前提，修改须过合规评审（`SRS-CN-SKILLS.md:14-16`）。

## 2. 预期用途（按法规措辞）

供 **病案/编码员、药学专业人员、医保办** 使用：

- 作为医院信息系统（HIS/EMR）的辅助模块，对 **已产生的处方/病历文本**（非医疗器械数据，符合2021-47号举例“患者主诉等信息”）进行 **条文/术语一致性比对与证据定位**，输出供专业人员复核的参考信息；
- **不向医师/药师生成治疗建议文本**，所有需判断项转人工 signoff；
- 审方规则的依据来源由医疗机构从国家医保局/NMPA公布文件或本院存档导入并确认（对应《处方审核规范》2018-14号第八条）。

## 3. 三层分类判定自评（核心）

| 判定 | 条件（2021-47号原文） | 本产品匹配 | 后果 |
|---|---|---|---|
| 不作为医疗器械管理 | 处理非医疗器械数据且不用于医疗用途 | 不满足（用于医疗用途）| 此路不通 |
| **Ⅱ类（目标）** | 非辅助决策：数据处理/比对，提供临床参考信息 | **主张**：见 §4 论据链A | 省局 60日审评 |
| Ⅲ类（风险） | 辅助决策（含“用药指导”）+ 算法成熟度低 | 风险：见 §5 论据链B | 国家局 90日 + 临床试验 36-48月 |

## 4. 论据链 A（主张Ⅱ类）— 非辅助决策

1. 处理对象为 HIS/病案系统的文本记录，非医疗器械产生的数据；
2. 核心为 **说明书/目录条文的精确比对与定位**，判定由规则引擎（条文匹配+剂量公式+相互作用表）产生，LLM仅做实体抽取（`prescription-review/SKILL.md:17` “LLM无判定权”）；
3. 输出封闭四态，其中三态均为转人工，不生成自然语言治疗建议；
4. 依据来源由医疗机构导入并版本化（`packs/README.md` source_version/effective_date 门控）。

## 5. 论据链 B（预先回应监管可能的反认定）

1. FLAG 是否影响用药流转 → 可能被认定为辅助决策；
2. LLM 参与自由文本理解 → 触“AI医用软件”定义 → 成熟度低+辅助决策=Ⅲ；
3. **应对**：D1-D5 降险架构已锁进代码与文档（见 02-device-description.md），且同业以Ⅱ类持证为常态（粤械注准20202210206，`EVIDENCE-PRIOR-ART.md:8-11`）。

## 6. 使用场景与人群

- **使用人**：执业药师（第一责任人）、病案编码员、医保办专员
- **使用环境**：医院内网私有化部署，本地 stdio，无境外数据传输
- **患者人群**：不直接接触患者；处理脱敏后处方/病历文本，原文经 phiguard 脱敏后才入审计/日志（`PRIVACY-SECURITY.md:8-12`）
