# 01 预期用途说明书（分类界定送审草案）

> 依据《人工智能医用软件产品分类界定指导原则》（国家药监局 2021 年第 47 号通告）、《医疗器械分类目录》（原国家食药监总局 2017 年第 104 号公告，子目录 21「医用软件」）及《深度学习辅助决策医疗器械软件审评要点》编制。

---

## 1. 产品名称与系统定位

**产品通用名称**：住院临床工作流数据辅助整理软件（插件版）  
**商品名/研发代号**：Medcius (v0.2.0-pilot)

### 1.1 系统架构与边界
Medcius 是安装于宿主 Agent（Codex、Trae、WorkBuddy 或医院自建 Agent）的 **只读临床信息系统辅助插件**，提供以下四大核心临床工作流信息整理能力：
1. **住院查房前患者演变摘要（`patient-evolution-summary`）**：自动融合过去 24/72 小时内的体征极值、检验动态、医嘱调整与未闭环检查，输出带原文 Span 绑定的结构化事实；
2. **临床交接班 SBAR 重点整理（`shift-handover`）**：基于 SBAR / I-PASS 模型，归纳夜间重点关注患者、监护极值与危急值；
3. **专科会诊前资料包整理（`consult-preparation`）**：紧扣专科会诊诉求，梳理专科病程时间轴与未回报检验；
4. **出院资料核对与完整性检查（`discharge-readiness-check`）**：核查关键检查检验闭环状态、出院带药医嘱与安全缺口。

### 1.2 禁止能力红线（Prohibited Actions）
- **禁止自主诊断与鉴别诊断**：不得输出“拟诊/确诊”或鉴别诊断概率排序；
- **禁止开立或调整处方**：不得出具处方推荐或自动下达医嘱；
- **禁止未经人工确认的自动写回**：所有生成的整理草稿必须由执业医师主动审核并手动确认，不得自动签名或绕过医师直接写回 EHR。

## 2. 预期用途与使用场景

### 2.1 预期用途（法规合规表述）
作为医疗机构信息系统（EHR / LIS / PACS / NIS）的**只读数据整理与信息展示辅助模块**，对医疗机构内已产生并经授权的病历文本、检验测量值、影像检查报告和医嘱记录（非医疗器械原始信号数据，符合 2021 年第 47 号通告举例之“已产生的文字记录与测量数据”）进行**跨系统客观结构化提取、演变趋势计算与证据定位呈现**，为执业医师提供查房、交接班及会诊前的资料复核参考。

### 2.2 目标用户与使用环境
- **目标用户**：具备相应资质的注册执业医师、住院医师、主治医师及临床质控人员；
- **使用环境**：医院局域网内私有化部署、前置机离线环境或经授权的本地宿主 Agent。原始医疗数据在院内假名化处理后仅存于瞬时内存，不进行境外数据传输。

## 3. 分类判定自评论据

| 判定维度 | 监管指导原则标准 (2021-47号 / 2017-104号) | 本产品匹配事实 | 判定结论 |
|---|---|---|---|
| **处理数据性质** | 处理已记录的文字、检验数值等非生理原始波形数据 | 处理 EHR/LIS/PACS/HIS 已归档文本与结构化结果 | 符合信息处理特征 |
| **功能定位** | 非辅助决策：仅进行数据检索、统计、重组与客观呈现 | 仅提取事实与计算代数和/变化率，不提供诊疗结论 | 属于非辅助决策 |
| **算法成熟度** | 规则驱动 + 确定性计算，LLM 仅限客观实体与 Span 抽取 | 判定逻辑全部由版本化规则包完成，LLM 无临床判定权 | 算法风险低 |
| **责任归属** | 医生对所有信息进行核对，承担最终临床责任 | 界面显式标注来源 Span，缺失信息显式报警 | 人工把关完整 |

### 3.1 申报分类建议
依据《医疗器械分类目录》子目录 21「医用软件」- 02「临床信息系统」- 01「医院信息管理软件」：
- **主张申报类别**：**第二类医疗器械**（或作为医疗信息化软件不作为医疗器械管理）；
- **预期管理类别代码**：21-02-01 或 21-03（数据处理软件）。
