# 软件版本命名规则（MNT-01）

> **状态**：v1 草案，待 QRA 批准。依据《医疗器械软件注册审查指导原则（2022 年修订版）》（器审中心通告 2022 年第 9 号）对软件版本命名规则的要求：字段位数、范围、含义明确，能区分重大软件更新与轻微软件更新。

## 1. 版本结构

```
发布版本（发布版本号）：V<major>.<minor>            → 注册证/说明书/市场材料使用
完整版本（完整版本号）：<major>.<minor>.<patch>+b<build> → 内部与审计链记录使用
```

| 字段 | 位数 | 范围 | 含义 |
|---|---|---|---|
| major | 不限（递增） | ≥1 | 重大软件更新：预期用途、核心功能、核心算法（含判定逻辑架构）变化 |
| minor | 不限 | ≥0 | 重大软件更新中的功能级新增/删除；技能集或 MCP server 增删 |
| patch | 不限 | ≥0 | 轻微更新：缺陷修复、文案、提示词微调、样例数据 |
| build | 不限 | ≥0 | 构建元数据（git 短哈希），不参与更新类型判定 |

## 2. 更新类型判定矩阵

| 变更内容 | 类型 | 字段动作 | 合规动作 |
|---|---|---|---|
| 预期用途措辞 / 输出模板四选一语义 / G1–G3 门控逻辑 / 判定确定性边界（D1/D2） | **重大** | major+1, minor=0 | 变更评审 + 分类界定影响复核 + 全量回归 + 审计链记录 |
| 新增/删除技能或 MCP server | **重大** | major+1 或 minor+1（视是否改变核心功能集） | 同上 |
| 语料 schema 变更（导入格式、data_class 语义） | **重大** | minor+1 | 变更评审 + 导入器回归 |
| 官方语料版本更替（同 schema，如医保目录年度更新） | 轻微 | patch+1 | `import-official` 记录 source_version/effective_date + 审计链事件 |
| 提示词/SKILL 文案微调（不改 must/must_not 断言集） | 轻微 | patch+1 | `run-evals` 回归零 fail |
| 评测用例增补（需求集扩大） | 轻微* | patch+1 | 重跑 gen-dhf-trace 同步矩阵；若删除用例则升为重大 |
| 缺陷修复、依赖升级、文档 | 轻微 | patch+1 | 回归 |

\* 用例增补改变需求集规模，注册后涉及许可事项变更的判断 [待批：以顾问意见为准]。

## 3. 版本事实来源（单一真相）

1. **git tag**（`v<major>.<minor>.<patch>`）为唯一发布事实；
2. `plugins/medcius/plugin.json` 的 `version` 与 tag 一致（CI 校验点 ⬜ 待加）;
3. 每次发布把 tag + 全部语料 snapshot 哈希经 audit `record_event` 写入审计链（对应 SRS MNT-03）——回答"这个判定依据哪个版本"时，审计链是机器答案。

## 4. 与监管要求的对照

- 区分重大/轻微 ✅ §2 矩阵
- 字段含义明确无歧义 ✅ §1 表
- 涵盖全部更新类型 ✅ §2 首列枚举
- 变更历史可追溯 ✅ git + 审计链双轨
