# Medcius：帮助医生整理患者变化、待跟进事项与资料缺口

Medcius 是面向一线临床医生的 **Agent 插件**，可以理解为给医院批准的 AI 助手增加一套临床资料整理工具：从获得授权的病历、检验、影像报告、护理和医嘱来源中整理信息，让医生看到患者近期有哪些变化、哪些事项还需要跟进，以及每条信息的原始出处。

它的目标是减少查房前寻找和拼接资料的负担。医生提出任务、核对证据并作出医学判断；AI 助手负责组织任务，Medcius 负责受约束地读取、整理和呈现资料。

**当前版本是 0.8.0-pilot 工程试点版。** 已有软件实现、合成病例验证及实际容器验证；尚未完成真实医院接入验收和临床效果验证。当前院内入口的上限是查房流程的静默试点：在后台计算、保留复核记录，不向临床医生展示摘要或弹出提醒，也不生成病程草稿。下面介绍的是现有实现与工程演示所体现的能力，不能理解为已经在病区常规开放。

**首先解决的是查房前的资料整理。**

一个典型的任务表达是：“整理这位患者过去 24 小时的变化，把未出结果的检查、尚未完成的事项和关键资料缺口分别列出来，并保留来源。”

系统将结果组织成四部分：

| 医生关心的问题 | 整理出的内容 |
|---|---|
| 最近发生了什么变化？ | 病程中的症状变化、体征记录、检验趋势、出入量资料，以及医嘱新增、停用或调整；计算以具备相应时间和单位的来源记录为前提。 |
| 还有什么需要跟进？ | 已开立但执行状态未确认的检查、尚未出最终报告的检验，以及已有结果但缺少医生确认记录的事项。 |
| 哪些资料还不充分？ | 过敏史未明确记录、缺少基线值或参考范围、来源系统未同步、记录版本冲突等。 |
| 这些信息从哪里来？ | 对应的原文片段或源记录，以及可获得的记录、采样、报告时间和版本信息。 |

这里保留几种临床上容易混淆的区别：医嘱已开立不等于已经执行，报告已出不等于医生已经确认，未记录过敏史不等于无过敏，接口没有返回资料不等于检查结果阴性。更正后的报告也不能沿用旧版本的确认状态。

**中文病历的措辞会影响摘要中的事实状态。**

例如，合成文本“无发热、咳嗽、胸闷，偶有咳痰”中，前三项应标为否定，“咳痰”仍是有记录的症状；“肺炎待排”“R/O 肺炎”保留为待确认；“10 年前行阑尾切除术，术后恢复可”保留为既往事件和相应恢复描述。项目已经实现这些中文断言规则及相应测试，并保留原文位置，供医生核对。对真实病历的准确性仍需要专门验证。

**与 Agent 的协作围绕明确任务和可核对的资料展开。**

拟采用的临床交互方式是在院内患者页面或医院批准的 AI 助手中获得患者、就诊与身份权限，再由医生指定整理任务。宿主 Agent 调用相应工具，Medcius 校验患者与就诊、读取授权来源、处理隐私信息，再返回带来源的整理结果。工程演示中可查看资料条目及证据；浏览、勾选或提出问题本身不构成临床签字、结果确认或事项关闭。

系统不自主下诊断、制定治疗方案、开立或修改医嘱，也不自动写回病历。查房摘要反映指定截止时间的资料，不能替代床旁评估或医院既有的危急值通知渠道。

**其他工作流已有实现，但开放范围需要分别看待。**

| 模块 | 已实现的整理范围 | 当前状态 |
|---|---|---|
| 查房前患者变化摘要 | 变化、待跟进事项、资料缺口和原始证据 | 首个临床试点范围；院内入口目前仅允许静默处理，真实接入待验收。 |
| 交接班准备 | SBAR/I-PASS 资料、来源医嘱、医生实际记录的预案及交接状态 | 保留工程和合成测试路径；临床入口冻结。 |
| 会诊前资料准备 | 围绕明确会诊诉求，从同一份资料快照整理不同专科的资料视图 | 保留工程和合成测试路径；临床入口冻结，不生成会诊意见。 |
| 出院资料核对 | 结果资料、在院与出院用药衔接、后续安排及费用可获得性资料 | 保留工程和合成测试路径；临床入口冻结，资料齐备不代表可以出院。 |

病案首页和医保结算清单的要素核对属于另行限定的用途，未纳入当前一线查房开放范围。上述工作流各自需要验证，不能因为查房流程通过测试，就认为其他流程也获得临床准入。

**本土化支持正在落实到具体资料核对上。**

代码中已加入中国 MDRD 和中国成人 BMI 的计算参考接口，以及 Padua/Caprini 评估记录完整性核查；还有部分单病种和核心制度记录节点、围术期预防用药记录、抗菌药分级与相关培养及授权记录核对。药学接口支持审校后的中西药成分重叠、具体中药注射剂配伍资料，以及医保类别、地方双通道、集采与限定支付范围等信息。

这些能力依赖适用人群、完整来源和院内审校后的规则及目录。目前没有完整正式药品说明书和地方支付目录，也没有院方审批的生产规则包。资料不足时会显示缺口；不能把它宣传为完整审方系统、全院质控达标统计或自动报销判定工具。接入时需要临床科室、药学部门、信息部门及相应管理部门共同核定范围。

**隐私和身份核对是处理流程的前置条件。**

生产路径在自由文本进入模型、日志或导出前，强制执行本地双轨脱敏：结合本次患者资料中的身份实体词典，以及本地运行的人名、地址等实体识别模型。模型缺失、扫描失败或患者身份不匹配时，相关处理会停止。检查通过仍不等于保证识别出所有隐私信息；原始数据是否离院，还取决于医院批准的模型、宿主、网络、日志和遥测部署边界。真实病历不能直接复制到未经批准的通用聊天环境。

**对一线医生，目前最合适的参与方式是用合成病例核对它是否忠实表达资料。**

可以重点看：有没有漏掉应展示的变化，是否混淆旧结果与新结果，是否误解否定和待排，缺失信息是否被错误补全，以及能否准确找到原始出处。完成院内授权和接入验收后，再按批准方案开展真实病例的独立复核和静默验证。

最近一次本地全量检查完成了 89 个步骤，其中 76 项工程检查通过、13 项报告或基准脚本完成；实际容器完成 18 步验证，包含 31 项 NER/PHI 测试。这些结果说明软件路径与所测试的失败处理已经受检，不能换算为临床准确率或医生节省的时间。是否真正减少遗漏、降低核对负担、节省医生时间，仍需真实临床研究回答。
