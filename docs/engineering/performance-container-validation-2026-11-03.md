**性能定位与已采用的修复**

原始剖析中，一次查房触发 246 次原生 ONNX 推理，只有 39 组不同的 token 输入；同一文本被桥接、适配器、引擎以及残留检查反复扫描。当前最终源码剖析为每次 45 次原生推理，保留模型、输入文本、单条推理形状和标签解码方式。原始计数见 `baseline-token-profile.json`，最终计数见 `final-profile.json`；剖析时间不是门禁成绩。

新增 `phi-inference-scope.mjs`，仅在一次被等待的临床操作内复用已核验 detector 对完全相同文本的原始结果。作用域绑定租户、患者、就诊、医师及会话/请求 ID，结束即清空，限制条目数与文本字节数；没有跨请求缓存或持久化 PHI。每个边界仍运行当前实体词典、文本摘要、实体范围、正则及残留检查；发生文本变化就重新调用 detector。回执区分 detector 调用与结果复用，不能把逻辑检查轮数当作原生模型调用次数。

模型缺失/损坏/关闭、原生推理失败、取消、超时、错配或残留均继续阻断。一次操作中任何 NER 失败会使整个作用域失败；即使调用方捕获内层异常，也不能把整次操作作为成功返回。负对照覆盖新请求重新执行模型、并发患者隔离、动态词典追加、返回结果被修改、错误/取消后的旧结果拒绝、关闭模型拒绝。

**Docker 与校验环境**

Docker 原因是数据盘残留在 Windows 挂载中，WSL 再挂载遭到共享冲突，另有不可访问的旧通信端点。保留端点目录备份；在确认目标盘和停止 Docker 后，通过 Windows 管理员步骤卸载残留挂载，随后正常启动。没有重置 Docker、删除镜像/卷、格式化数据盘或停止其他运行中的 WSL 工作。

实际镜像按仓库 Dockerfile 构建，锁文件安装依赖，宿主 node_modules 不进入镜像，模型只读挂载。下载前核对了约 78.3 MB 基础镜像层及约 97.7 MB 依赖包；没有重新下载模型。验收使用非 root、只读根文件系统、禁用外部网络、不发布宿主端口的临时容器，覆盖真实 CPU 推理、缺/坏模型、缺原生依赖、缺 TLS、服务启动缺模型、HTTPS 健康检查、不可信证书拒绝和合成 MCP/查房/审计/文档链路，测试容器已停止。
