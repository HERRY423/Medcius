**性能修复与安全不变量**

1. 本地 ONNX 推理采用逐文本独立量化的批处理执行图。普通动态量化批处理会跨文本共享量化范围，试验已出现标签变化，因此未采用。新图严格校验原模型摘要，分别计算每条输入的量化范围，排除 padding；仅合并 Q/K/V 的执行与使用等价的 CPU 注意力算子。整数中间值上界 7,292,745 小于 2^24，由权重计算并强制检查。权重、词表、8 位精度、标签、窗口、重叠及解码阈值均未改变。
2. 四个本地 worker 各使用两个推理线程，批次最多 12 个窗口；按长度分组及工作量排序，小批次并行分派。只在同一次请求内对相同 token 输入去重，按各原文重新绑定 UTF-16 范围与文本摘要；新请求仍执行实际 NER。HIS 输入收集范围与原字段策略相同，神经预扫描完成后仍逐字段运行当前词典、范围/摘要验证及残留扫描。正则干净结果、字段键规范化和词典扫描仅在受限操作/会话内缓存，注入新词典、失败或结束时失效。
3. 空闲原生线程改为等待，减少多个推理会话与 JavaScript 遍历之间的忙等争用；不修改浮点近似或精度选项。ONNX Runtime 1.23.2 的 [Node 配置实现](https://github.com/microsoft/onnxruntime/blob/v1.23.2/js/node/src/session_options_helper.cc) 与[线程选项定义](https://github.com/microsoft/onnxruntime/blob/v1.23.2/include/onnxruntime/core/session/onnxruntime_session_options_config_keys.h)支持该设置。新配置下逐值等价性在 Windows 与 Linux 都通过。
4. 去掉把 `[ID:…]` 等不可能是 JSON 的标记反复解析为 JSON 所触发的异常；文本仍完整进入 PHI 检查。负对照覆盖标记后拼接裸姓名/电话、真实嵌套 JSON 和序列化身份对象，未增加文本或字段白名单。
