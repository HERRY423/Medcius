# 中文病程脱敏反例修复与并发实测

上一轮留下的 5 个身份遮盖缺口与 7 段临床文字误删全部修复。原 120 条样例中，最终版恰好改变了这 12 条的输出。两组新挑战显示，临床文字保留改善，裸姓名完整遮盖数与改前相同。本机 64 请求补查密集负载的每轮 p95 均值较上一版下降 30.7%，12 轮均零拒绝。

## 身份与临床文字

各分数均按原文 UTF-16 位置计算。实体必须完整遮盖，应保留段必须所有字符完整保留。以下各组均为人工编写的合成输入，阻断数均为零。

|---|---:|---:|

| 新挑战 A，100 条 | 50/60 → **50/60** | 142/144 → **143/144** |
| 新挑战 B，72 条 | 31/36 → **31/36** | 104/108 → **108/108** |

开发回归中的“查祎”和“闻人泠”共出现于五个出错语境。重放确认，完整句子与精确姓名片段的神经模型预测均缺失 PERSON。新规则只在有界病程主语位置、片段推理成功完成后，检查姓氏和有限的名字用字组合。命中时在回执中标明 `surname_subject_rule`，保留原神经预测。该规则不写入患者身份词典。完整出处可见[改前重放](verification/phi-v5/diagnosis-before.jsonl)、[改后重放](verification/phi-v5/diagnosis-after.jsonl)和[最终 120 条回归](verification/phi-v5/development-120.json)。

临床修复覆盖了三个不同的边界。模型曾将“窦缓无头晕”中的“窦缓无”识别为人名，因而一并删除否定词。现在仅保护匹配到的句首心律描述及极性词。腓总神经的部分字符只有在明确查体等语境中享有保护。厚朴、葛根、牡丹皮的药名保护依赖具体用药或处方语法，其中“牡丹皮”的地点误标还须匹配整个药名。已知患者身份仍优先遮盖。旧有 24、80、125 条开发集分别保留了 19/19、36/36、34/34 个身份实体的完整遮盖和 28/28、150/150、139/139 处临床文字。[旧开发集复测](verification/phi-v5/development-v1-v3.json)

新挑战 A 在识别改动前固定，在第一次实现冻结后打开。之后只调整调度，最终版逐条重放，全部 100 个输出与第一次一致。挑战 A 剩余 10 处身份遮盖缺口和 1 段临床文字损失，后者出现在泽兰用药语境。新挑战 B 在第二次调度改动前固定，在最终实现冻结后首次评估。剩余五处身份缺口为“闻人晞”的三个语境和“南宫湛”的两个语境。两个集合和旧开发文本没有完全相同的句子，构造者相同，反复使用相近句式和同一合成姓名，样例数不能当作独立患者数。证据支持修复已知反例和改善所测临床文字保留，对未见姓名召回改善仍证据不足。[挑战 A 前后结果](verification/phi-v5/challenge-results.json) · [最终版逐条复核](verification/phi-v5/replay-100.json) · [挑战 B 冻结记录](verification/phi-v5/final-holdout/freeze.json) · [挑战 B 前后结果](verification/phi-v5/final-holdout/challenge-results.json)

## 真实 CPU 执行与请求延迟

补查片段继续使用 v4 的均衡分批。最终版也将同一个长度组内的短整句分给已有 Worker，每组超过 4 行且每行至多 32 token 时启用。每个原生批次至多 12 行。三个版本各自在同一台 14 逻辑核 Windows 机器运行，使用 2 个进程、每进程 2 个 Worker、每 Worker 2 个原生线程，CPU 预算为 8，队列上限与请求截止规则相同。

| 本机负载 | 调度优化前 v3 | 上一版 v4 | 最终版 v5 |
|---|---:|---:|---:|
| 8 个片段组件耗时，12 轮均值 | 27.67 ms | 本组未测 | **17.96 ms** |
| 64 请求补查密集，12 轮 p95 均值 | 662.16 ms | 628.67 ms | **435.62 ms** |
| 上述 64 请求，完成 / 拒绝 | 768 / 0 | 768 / 0 | **768 / 0** |
| 64 请求原混合快照，6 轮 p95 均值 | 本组未测 | 3142.00 ms | **3092.75 ms** |
| 上述混合快照，完成 / 拒绝 | 本组未测 | 384 / 0 | **384 / 0** |

补查密集对照在六种版本顺序间轮换两遍，每次只有一版执行，每版 768 个完成请求均有实际补查回执。最终版在全部 12 对中均快于 v4，每轮 p95 差值为减少 102–298 ms。混合快照在 64 请求时降低约 1.6%，其 1、8、32 请求档分别约为 194 → 247、347 → 383、1597 → 1645 ms。组件在 8 片段时相对 v3 降低约 35.1%，在 24 和 25 片段时有所变慢。这些数值是指定机器、输入和负载下的测量。[三版本逐轮结果](verification/phi-v5/three-way-final.json) · [混合快照各档结果](verification/phi-v5/legacy-final.json) · [组件各档结果](verification/phi-v5/component-final.json)

开发中第一次修复仅改变识别。其 64 请求补查密集双版本对照为 v4 594.67 ms、修复版 636.93 ms。在随后三版本同场对照中，v3、v4、初次修复版分别为 592.26、578.71、588.92 ms。此结果促成短整句分批调整，保留全部测量记录以便比较宿主波动与改动效果。[初次双版本对照](verification/phi-v5/crop-v4-v5.json) · [初次三版本对照](verification/phi-v5/three-way.json)
