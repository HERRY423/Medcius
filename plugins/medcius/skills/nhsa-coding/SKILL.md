# 国家医保编码（NHSA Coding）— 查询与校验协议

**本技能是查询与校验协议，不是编码知识库。** 国家医保编码数据库持续动态更新（版本、扩展码、结算口径经常变化），因此：

- **模型不得凭记忆输出编码**——即使"确信自己知道"，也必须经连接器检索并校验后才可输出。
- **模型不负责记代码，只负责证明代码为什么成立**：从临床诊断出发，逐步检索、校验、确认可结算性，并为每个编码留下可追溯出处。
- **具体码值不属于 SKILL.md**。本文件只规定协议：查什么、怎么查、怎么验、怎么证明。
- **编码体系以连接器返回的 `code_system` 为准**，不用模型记忆假设体系。

## 阶段一：临床诊断（Clinical diagnosis）

从病历中确定**本次结算清单要反映的诊断与操作**（而非患者全部病史）。依据《医疗保障基金结算清单填写规范》：

1. **主要诊断** —— 本次住院/门诊诊治确定的、导致就医主要原因的疾病（或健康状况）
2. **其他诊断** —— 本次住院/门诊期间诊治的合并症、并发症
3. **手术及操作** —— 本次住院/门诊期间实施的手术和操作

**不纳入结算清单：**
- 不确定诊断（"疑似""待查""排除"等）不编码；编码主要症状
- 仅作为既往史提及、本次未治疗的疾病
- 与本次住院/门诊无关的慢性病（除非本次进行了诊治或调整了方案）
- 医保版中标注"不可作为主要诊断"的编码（如部分 Z 码）

## 阶段二：映射到 CN 临床术语（CN clinical terminology）

在**不推断、不升阶**的前提下，把每个诊断/操作转成医保体系使用的标准中文术语——此阶段产出**术语概念**，尚未编码：

- **只使用病历明确记载的表述**；不推断严重程度、分期、侧别、发作类型、并发症亚型
- **并发症/亚型必须由临床医生明确诊断**，不能仅凭检验值、影像学发现推断
- 药品用**通用名**；操作用病历中的手术/操作名称
- 术语不确定时先向用户/病历核实，不要自行补全

## 阶段三：NHSA 编码检索（NHSA code search）

对每个术语，使用**国家医保编码 MCP 连接器**检索候选编码——**包括你确信自己知道的编码**。检索是唯一合法的编码来源：

- `search_codes`（`code_type="diagnosis"`）检索诊断；查询词使用阶段二的术语
- `search_codes`（`code_type="procedure"`）检索手术操作；连接器返回的是**医保版手术操作分类编码**（以 ICD-9-CM-3 为基础），**不是 CCHI**
- `lookup_code` / `validate_code` 核对候选编码的完整性（含占位符与扩展位规则）
- 连接器返回的编码**照抄、不重新格式化**；返回的 `code_system`/`code_version`/`effective_date` 等字段一并记录

**编码体系边界（防止混用）：**

| 实体 | 结算清单使用的体系 | 发布方 | 备注 |
|---|---|---|---|
| 疾病诊断 | 医保版 ICD-10 | 国家医保局 | 与临床版（病案首页用）在部分编码上有差异 |
| 手术操作 | 医保版手术操作分类编码（ICD-9-CM-3 基础） | 国家医保局 | **不是 CCHI** |
| 医疗服务项目 | CCHI（全国医疗服务项目技术规范） | 国家卫健委/医保局 | 用于项目立项与收费定价，**不用于结算清单手术操作栏** |
| 药品 | 医保药品分类与代码 | 国家医保局 | 走药品目录连接器（见 nhsa-policy / nmpa-drugs） |
| 医用耗材 | 医保医用耗材分类与代码 | 国家医保局 | — |

> 体系名称与口径以国家医保局最新发布为准；具体每个编码的体系由连接器返回字段确认。本技能流程以结算清单的诊断与手术操作为主；药品/耗材编码走各自连接器。

**如果连接器工具不可用，停止。** 告知用户需要启用国家医保编码连接器，不要凭记忆输出编码——凭记忆产生的编码正是医保编码错误的主要来源。

## 阶段四：版本感知校验（Version-aware validation）

对每个候选编码，确认其**以当前生效版本**存在且完整：

- 记录并核对连接器返回的 `code_version` 与 `effective_date`；**连接器未暴露版本字段时如实标 `unknown`，`validation_status` 不得为 `valid`**
- 编码必须为**完整可结算长度**（含医保版占位/扩展规则）；不输出裸类目（J45、E11、N20 单独出现不可结算）
- "其他特指"(.8) ≠ "未特指"(.9)；只用病历明确记载的特异性
- 记录 `retrieved_at`（本次检索时间）与 `source`（返回该编码的连接器/端点）

## 阶段五：结算可及性校验（Settlement eligibility validation）

逐条确认编码可用于医保结算清单：

1. 病历是否显示该疾病本次被诊治、管理或处理？
2. 特异性是否与病历记载完全一致（未详细记载用未特指，详细记载用特指）？
3. 是否唯一编码、完整可结算、来自本次检索结果？
4. 是否"不可作为主要诊断"的编码（如是，调整主诊断选择或标注）？
5. 连接器若提供结算可及/目录状态字段，以其为准；否则按填写规范判断，无法确认项标为 `pending`

全部满足才保留。两个编码描述同一诊断时，删除其一。

## 输出格式（每个编码必须附带出处）

所有最终编码以结构化块输出，**六个出处字段缺一不可**；连接器无法提供的字段如实写 `unknown`，不编造：

```
主要诊断
  code: <连接器返回的完整编码>
  code_system: 医保版ICD-10
  code_version: <连接器返回版本；未知→unknown>
  effective_date: <该版本生效日期；未知→unknown>
  retrieved_at: <本次检索时间>
  source: <返回该编码的连接器/端点>
  validation_status: valid | pending | unverifiable

其他诊断
  - code: ...（同上七个字段）
  - code: ...

手术操作
  - code: ...
    code_system: 医保版手术操作分类编码（ICD-9-CM-3 基础）
    ...（同上七个字段）
```

- 编码与连接器返回的**完全一致**，不重新格式化
- `validation_status` 取值：`valid`（已通过校验）/ `pending`（需人工复核）/ `unverifiable`（连接器无法确认版本或结算状态）
- 任何为特定结算系统做的格式转换都在下游完成，不在此处进行

## 协议红线（不可协商）

1. **不凭记忆输出编码** —— 所有码值必须来自本次连接器检索结果
2. **不混用编码体系** —— 每个编码必须标注 `code_system`，且以连接器返回为准；CCHI 不用于结算清单手术操作编码
3. **版本不明确即标注** —— `code_version`/`effective_date` 缺失时，`validation_status` 不得为 `valid`
4. **连接器不可用即停止** —— 不降级为"凭经验编码"
5. **编码可追溯** —— 每个编码都附带完整出处；模型对"为什么成立"负责，而非对"记不记得"负责
