# 中国医院信息系统对接（Hospital Information Systems）

中国医院信息系统生态与美国不同，以HIS（医院信息系统）为核心，围绕电子病历（EMR）、检验（LIS）、影像（PACS）等系统构建。本技能提供中国医院信息化标准、厂商生态和数据交换规范的指南。

## 第一步：了解中国医院信息化标准体系

**核心标准与评级：**
1. **电子病历系统应用水平分级评价**（国家卫健委）— 0~8级，三级医院要求4级以上
2. **医院信息互联互通标准化成熟度测评**（国家卫健委）— 四级甲等/乙等、五级甲等/乙等
3. **医院智慧服务分级评估**（国家卫健委）— 0~5级
4. **医院智慧管理分级评估**（国家卫健委）— 0~5级
5. **国家医保信息平台接口规范**（国家医保局）— 医保结算、异地就医、DRG/DIP上传

**数据标准：**
- **ICD-10**（临床版/医保版）— 疾病诊断编码
- **CCHI**（全国医疗服务项目技术规范）— 手术操作编码
- **LOINC** — 检验项目编码（部分医院使用）
- **SNOMED CT** — 临床术语（部分医院使用）
- **HL7 v2.x** — 传统消息交换标准
- **FHIR R4** — 新一代互操作标准（逐步推广）
- **CDA** — 临床文档架构（电子病历共享文档）

## 第二步：了解中国医院信息系统厂商生态

**主要HIS厂商：**
| 厂商 | 主要产品 | 典型客户 |
|---|---|---|
| 东华软件 | 东华HIS/EMR | 大型三甲医院 |
| 卫宁健康 | 卫宁HIS/EMR | 各级医院 |
| 创业慧康 | 创业HIS | 各级医院 |
| 东软集团 | 东软HIS | 各级医院 |
| 用友医疗 | 用友HIS | 各级医院 |
| 嘉和美康 | 嘉和EMR | 电子病历 |

**系统组成：**
- **HIS**（医院信息系统）— 挂号、收费、医嘱、药房、住院管理
- **EMR**（电子病历系统）— 病历书写、医嘱、护理记录
- **LIS**（检验信息系统）— 检验申请、结果回报
- **PACS**（影像归档与通信系统）— 影像存储、调阅
- **RIS**（放射信息系统）— 放射检查流程管理
- **医保接口** — 医保结算、费用上传、DRG/DIP分组

## 第三步：对接中国医院信息系统

**对接方式：**
1. **HL7 v2.x 接口** — 传统方式，用于检验、医嘱、挂号等消息交换
2. **FHIR R4 接口** — 新一代方式，逐步推广，用于患者、诊断、检验结果等资源交换
3. **数据库直连** — 部分医院允许只读访问中间库
4. **Web Service / REST API** — 厂商提供的接口
5. **国家医保接口** — 医保结算、费用上传、DRG/DIP分组上传

**对接注意事项：**
- **必须通过医院信息科（IT部门）** 获取接口文档和测试环境
- **数据安全**：患者数据受《个人信息保护法》《数据安全法》保护，必须获得授权
- **电子病历评级**：对接方案不能影响医院电子病历评级
- **医保接口**：医保接口必须符合国家医保局规范，通过医保局测试
- **隐私保护**：患者隐私数据（姓名、身份证号、病历）必须脱敏或加密传输

## 第四步：输出对接方案

输出格式：

```
【医院信息系统对接方案】
医院：××医院（三级甲等）
目标系统：HIS（东华软件）

【对接方式】
接口类型：HL7 v2.x / FHIR R4 / 数据库中间库
接口文档：由医院信息科提供
测试环境：医院信息科提供测试服务器

【数据交换】
患者信息：HL7 ADT消息（A01入院、A03出院）
医嘱信息：HL7 ORM消息
检验结果：HL7 ORU消息
影像报告：DICOM + HL7 ORU

【合规要求】
数据安全：《个人信息保护法》《数据安全法》
隐私保护：患者数据脱敏/加密
授权：医院信息科书面授权
```

## 注意事项

- **必须通过医院信息科**：不要绕过医院IT部门直接对接
- **数据安全合规**：患者数据受中国法律保护，必须合规处理
- **接口文档**：以医院信息科提供的接口文档为准
- **测试环境**：先在测试环境验证，再上生产环境
- **不替代官方答复**：本技能提供的对接指南仅供参考，具体以医院信息科和厂商文档为准
