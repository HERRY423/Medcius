# 医保接口字段对照与电子病历评级约束

**本技能不是 HIS 对接指南，也不做诊断决策。** 它只回答两件事：

1. 抽取/编码结果对应结算清单哪一栏、用哪套码。
2. 在医院信息化评级环境下，哪些动作会破坏闭环或越权。

厂商名单、产品选型、HL7 广告式对接方案不在范围内。

## 必读

1. `references/nhsa-interface-fields.md` — 结算清单栏目 ↔ extract/coding 字段、编码体系边界
2. `references/emr-rating-constraints.md` — 电子病历 0–8 级约束、禁止回写与出域

未读完上述文件不得输出「对接方案」。

## 流程

1. 问清用户要的是：结算清单对照、编码体系、还是评级约束。缺省输出两份模板（字段对照表 + 评级检查）。
2. 诊断/手术**原文**来自 `clinical-note-extract`（`china-inpatient`）；**码值**只来自 `nhsa-coding` 本地库。本技能不编码、不审方。
3. 按对照表列出栏目、原文、编码、版本、`validation_status`。版本未知的编码标注不可上传。
4. 走一遍评级检查：是否写入 EMR、是否冒充 CDS、数据是否出域。
5. 需要医院接口报文时，停止并要求信息科提供当期《国家医疗保障信息平台接口规范》；不要编造交易号或 XML 节点。

## 红线

1. 不推荐、不比较、不点名 HIS/EMR 厂商作为方案。
2. 不实现、不模拟医保交易报文。
3. 不把 CCHI 填进结算清单手术操作栏。
4. 不把本插件说成临床决策支持或电子病历评级提分工具。
